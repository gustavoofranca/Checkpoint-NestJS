# Specification

## Product

Checkpoint is a game catalog service. It keeps a catalog in sync with public Steam store data,
serves it through a fast, cached, paginated HTTP API, and lets registered users review games
and keep a personal library. A small web UI consumes the API.

It is not affiliated with Valve or Steam. It stores only public catalog metadata.

## Goals

- Show production habits in a small codebase: modelling, migrations, auth, caching, background
  jobs, observability, tests, CI, documentation
- Stay small enough to be read end to end in under an hour

## Non-goals (do not build)

- Payments, subscriptions, email sending, password reset by email, social login
- File uploads, avatars, comments on reviews, friends, notifications
- Game downloads, launch features, or anything beyond public catalog metadata
- Microservices, Kubernetes, GraphQL, websockets
- Admin UI (admin actions are API only)

## Roles

- `anonymous`: read catalog, reviews and public profiles
- `USER`: everything above, plus manage own reviews and own library
- `ADMIN`: everything above, plus trigger and inspect catalog sync

There is no endpoint to create an admin. The first admin is promoted by a CLI seed command.

## Data model

All primary keys are UUID v7 generated by the application unless noted. All tables have
`createdAt`; mutable tables also have `updatedAt`. Timestamps are `timestamptz` in UTC.

**User**: `id`, `email` (unique, stored lowercase), `username` (unique, 3–24 chars,
`[a-z0-9_]`), `passwordHash`, `role` (`USER` | `ADMIN`, default `USER`)

**RefreshToken**: `id`, `userId` → User (cascade), `tokenHash` (unique), `familyId`,
`expiresAt`, `revokedAt` (nullable), `replacedById` (nullable). Index on `userId`, `familyId`.

**Game**: `id`, `steamAppId` (int, unique), `slug` (unique), `title`, `shortDescription`,
`headerImageUrl`, `releaseDate` (nullable date), `developers` (text[]), `publishers` (text[]),
`isFree` (bool), `priceCents` (nullable int), `currency` (nullable char(3)), `ratingAverage`
(numeric(3,2), default 0), `ratingCount` (int, default 0), `syncedAt`.
Indexes: `title` trigram GIN (pg_trgm) for search, `(releaseDate, id)`, `(ratingAverage, id)`.

**Genre**: `id`, `name` (unique), `slug` (unique)

**GameGenre**: `gameId`, `genreId`, composite primary key, index on `genreId`

**Review**: `id`, `userId` → User (cascade), `gameId` → Game (cascade), `rating` (smallint,
CHECK 1–5), `body` (text, 10–2000 chars), unique `(userId, gameId)`, index `(gameId, createdAt)`

**LibraryEntry**: `userId`, `gameId`, composite primary key, `status`
(`BACKLOG` | `PLAYING` | `COMPLETED` | `DROPPED`), `updatedAt`

**SyncRun**: `id`, `trigger` (`SCHEDULED` | `MANUAL`), `status`
(`RUNNING` | `SUCCEEDED` | `FAILED`), `startedAt`, `finishedAt`, `gamesProcessed`,
`gamesFailed`, `errorMessage` (nullable, truncated to 500 chars)

`ratingAverage` and `ratingCount` on Game are denormalized. They are updated in the same
transaction as the review write.

## API

Base path `/api/v1`. JSON only. Errors follow RFC 9457 Problem Details
(`application/problem+json`) with `type`, `title`, `status`, `detail` and, for validation
errors, an `errors` array of `{ field, message }`.

### Pagination

Cursor based on every list endpoint. Query: `limit` (1–50, default 20), `cursor` (opaque,
base64url of the sort key and id). Response: `{ data: [...], nextCursor: string | null }`.
An invalid cursor returns 400. No offset pagination and no total counts.

### Auth

| Method | Path | Auth | Notes |
|---|---|---|---|
| POST | `/auth/register` | none | email, username, password (min 12 chars). 201 with the user. |
| POST | `/auth/login` | none | Returns the access token in the body and sets the refresh cookie. |
| POST | `/auth/refresh` | refresh cookie | Rotates the refresh token. |
| POST | `/auth/logout` | refresh cookie | Revokes the token family. 204. |
| GET | `/auth/me` | access token | Current user. |

Login and register failures must not reveal whether an email is registered.

### Catalog

| Method | Path | Auth | Notes |
|---|---|---|---|
| GET | `/games` | none | Filters: `q` (title search, 2–64 chars), `genre` (slug), `sort` (`newest` \| `top_rated` \| `title`). Cached. |
| GET | `/games/:slug` | none | Game with genres and rating summary. Cached. |
| GET | `/genres` | none | All genres with game counts. Cached. |

### Reviews

| Method | Path | Auth | Notes |
|---|---|---|---|
| GET | `/games/:slug/reviews` | none | Newest first, with author username. |
| PUT | `/games/:slug/reviews/me` | USER | Creates or replaces the caller's review. |
| DELETE | `/games/:slug/reviews/me` | USER | 204. |

The API has no route that takes a review id for writing, so a user can only ever touch their
own review. Keep it that way.

### Library and profiles

| Method | Path | Auth | Notes |
|---|---|---|---|
| GET | `/me/library` | USER | Filter by `status`. |
| PUT | `/me/library/:gameId` | USER | Body: `status`. Upsert. |
| DELETE | `/me/library/:gameId` | USER | 204. |
| GET | `/users/:username` | none | Public profile: username, join date, review count, latest reviews. Never email. |

### Admin

| Method | Path | Auth | Notes |
|---|---|---|---|
| POST | `/admin/sync` | ADMIN | Enqueues a sync. 202 with the run id. 409 if one is already running. |
| GET | `/admin/sync/runs` | ADMIN | Recent runs. |

### Operations

| Method | Path | Notes |
|---|---|---|
| GET | `/health/live` | Process is up. |
| GET | `/health/ready` | PostgreSQL and Redis reachable. |
| GET | `/metrics` | Prometheus format. Requires a bearer token from `METRICS_TOKEN`. |
| GET | `/docs` | Swagger UI. Disabled when `NODE_ENV=production` unless `ENABLE_DOCS=true`. |

## Catalog sync

- Source: Steam store `appdetails` endpoint. It is unofficial and rate limited. **Verify its
  current behaviour and limits before implementing**, and write what you found in an ADR.
- The list of app ids to sync is a curated file committed to the repo
  (`api/prisma/data/steam-app-ids.json`, about 200 well-known games). Do not crawl the full
  Steam app list.
- A repeatable BullMQ job runs every 24 hours. Admins can also trigger a run.
- One request at a time, with a delay between requests that stays well under the limit, and
  exponential backoff with a retry cap on 429 and 5xx.
- Each response is validated with a schema before use. Invalid or missing entries are counted
  in `gamesFailed` and skipped; one bad game never fails the run.
- Upsert by `steamAppId`. Genres are upserted by name.
- When the run ends, the catalog cache is invalidated.
- A seed command loads a bundled snapshot so the project works offline and in CI without
  calling Steam.

## Web UI

Four screens, described in `docs/DESIGN.md`: catalog, game detail, sign in / sign up, profile
with library. Read-only for anonymous users.

## Quality bars

- p95 under 50 ms for cached catalog reads and under 200 ms uncached, on the seed dataset,
  measured with a short load test whose result goes in the README
- Line coverage of at least 85% on the API
- Zero high or critical findings in `npm audit --omit=dev`
